# AGENTS.md

Clavel evaluates Nix flake references — `evaluation`s — into deployment descriptions (early-stage WIP). A flake reference already encodes source and target in one string (`<source>#<evaluation-target>`); `Evaluation` is the core entity, stored via the API. Two runtime binaries: `clavelapi` (Connect/gRPC-over-h2c API backed by etcd) and `clavelcontroller` (watches evaluations via the API and dispatches with rules). `nix` is a **runtime** dependency, not just a build tool — evaluation happens via `nix eval --eval-cache --json`.

## Commands

Dev environment comes from the Nix flake (`direnv`: `.envrc` → `use flake .`). Tools and helper scripts (`develop-*`) are only on PATH inside `nix develop`; they are defined in `flake.nix`.

```sh
go build ./...        # builds; clavelapi, clavelcontroller, clavelctl, clavel-gen, nix-parallel-eval
go test ./...         # runs internal/core unit tests; compile-checks the rest
buf generate          # regenerate committed protobuf code (see below)
buf lint && buf breaking  # proto checks; buf.yaml points at api/
nixfmt-tree           # nix formatter (flake formatter); gofmt for Go
go run ./cmd/clavelctl apply <flake-ref> [--config <name>] [--address <host>]  # evaluate flake#clavelConfigurations.<name> and push to clavelapi
```

Dev/watch helpers (run from a `nix develop` shell):
- `develop-start-services` — starts etcd, required by `clavelapi` (hardcoded `localhost:2379`).
- `develop-watch-clavelapi` — hot-reloads clavelapi on `PORT=8080`.
- `develop-watch-clavelcontroller` — hot-reloads the controller (hardcoded `http://localhost:8080`).
- `develop-debug-clavelapi` — runs the API under delve.
- `go run ./cmd/nix-parallel-eval <ref>#<target> [<ref>#<target> ...]` — standalone debug CLI evaluating one or more flake references in parallel.

Integration flow: start etcd → `clavelapi` (PORT 8080) → `clavelcontroller`.

## Protobuf codegen

- Protos live under `api/clavel/**`. Generated Go (`*.pb.go`, connect stubs) is **committed** under `pkg/api/` and generated with `buf generate` (see `buf.yaml` + `buf.gen.yaml`; `out: .` + `module=` opt maps output to `pkg/api/`).
- Always run `buf generate` after editing a `.proto`. The `clavel-gen` protoc plugin (registered in `buf.gen.yaml` with per-integration `opt` params) emits the `nix/generated/*.nix` CRD descriptors/`spec` types in the same pass. Hand-written converter/setter files (e.g. `pkg/api/core/v1/evaluation_converter.go`, `evaluation_setter.go`) live next to generated code and are also tracked — extend them rather than editing `.pb.go` by hand.

## Structure

- `cmd/clavelapi` — API server; `PORT` env (default 80), no TLS; Connect RPC over h2c.
- `cmd/clavelcontroller` — generic reconciler: watches CRDs via the API, fans each registered kind's resources into workers that resolve the referenced `Evaluation` (`nix eval`), write back `EvaluationStatus`, and invoke the kind's **action module** (`<actionModule>.reference` transforms the eval ref, `<actionModule>.apply` yields a deploy action) before executing it. Action modules live in `modules/actions/*.nix` (e.g. `clavelActions.nixos`); stub-verifiable via `nix eval --json <flake>#<attr> --apply 'f: f "..."'`.
- `internal/genericstore` — generic etcd-backed KV store: resources JSON-serialized under `/<path>/<name>`; `resource_version` = etcd `ModRevision`.
- `internal/core` — per-resource-type files (`metadata.go`, `evaluation.go`, `crd.go`, `resource.go`) each holding the type plus its defaults/merge/validation; `*_service.go`/`*_store.go` per resource; `internal/fieldmaskcommander` — field-mask updates.
- `internal/core/crd_service.go`/`resource_service.go` — CRD registry (schema immutable once registered; idempotent re-apply, conflicting re-apply rejected) and generic custom-resource service. Resource specs are protojson bytes validated at runtime via the CRD's embedded `FileDescriptorSet` (`internal/core/spec_validation.go`, `dynamicpb` + `protoregistry`, `protovalidate` for embedded constraints). Storage: CRDs under `/crd/<group>/<version>/<kind>`, resources under `/resource/<group>/<version>/<plural>/<name>`. `cmd/clavelapi/crds` + `cmd/clavelapi/resources` mount the Connect handlers.
- `internal/utils/parallel_nix_eval.go` — calls out to `nix eval` for evaluation references (`<source>#<evaluation-target>`).
- Nix side: `lib.nix` `clavelDefinition` runs a module system over `imports` + `<kind>s.*` attrs producing an apply descriptor (`customResourceDefinitions`, `resources`, `evaluations`) for `clavelctl apply`. `modules/nixos.nix` is the `nixos` clavel module (registers the `NixosUnit` CRD, declares `nixosUnits` + typed `nixosUnitSpecs`, emits resources/evaluations); its CRD schema and spec type come from `nix/generated/nixos.nix`, generated by the `clavel-gen` protoc plugin (`cmd/clavel-gen`, registered in `buf.gen.yaml` with per-integration `opt` params) from `api/clavel/units/nixos/v1/nixos_unit.proto`. `flake.nix` exposes `clavelModules.nixos` and `clavelActions.nixos`; regenerate with `buf generate`.
- `example/` — a consumer flake importing this repo as `path:../`, exercising `flakeModule` + `lib.mkNixosUnit`; useful for sanity-checking flake-level changes.

## Conventions

- Errors wrap the sentinel package `internal/exceptions` via `errors.Join`.
- Commit messages are lowercase, conventional-style (`feat:`, `refactor:`, `chore:`, `format:`).
- `.direnv` and `.develop*` (etcd data dir) are gitignored; never commit them. No CI and no tests exist yet.
